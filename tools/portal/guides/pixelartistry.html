← 入口ページ ComfyUI を開く（ポート 8188）→

1. できること（ワークフローの一覧）

ComfyUI の左の Workflows から開く。PixelArtistry の 4 本は PixelArtistry フォルダ、Image_to_3D は一番上にある。

ワークフロー入力できるもの形を作るモデルの既定
01 Image to Watertight Mesh画像 1 枚閉じた 3D メッシュ（1536 の細かさ。3D プリントの元にも使える）Pixal3D
01b Image to Watertight Mesh 2K画像 1 枚01 と同じものを 2048 の細かさで。時間と RAM が多くかかるPixal3D
02 Image to GameReady Asset画像 1 枚テクスチャ付きの高ポリと、それを焼き込んだゲーム用の低ポリPixal3D
03 Your Mesh to GameReady Asset手持ちのメッシュ（.glb / .obj）と、その元の画像手持ちのメッシュにテクスチャを付け、ゲーム用の低ポリも作るTRELLIS.2（変えない）
Image_to_3D画像 1 枚テクスチャ付きの 3D モデル（閉じているとは限らない）。ポリゴン数とテクスチャサイズを入力欄で決めるPixal3D

4 本の PixelArtistry には、開くと画像の置き場（Load Image）の真上に緑の日本語ノート「使い方（日本語・この機体）」がある。英語のノート（Start here・Settings）は配布元のまま。

2. Pixal3D と TRELLIS.2 の違い

関係

  • TRELLIS.2 は Microsoft の画像 → 3D のモデル（TRELLIS.2-4B）。Pixal3D は Tencent ARC が TRELLIS.2 の仕組みの上に作ったモデル。
  • ComfyUI は 2 つを同じ型（Trellis2）として読み込む。形とテクスチャの VAE、画像の特徴を取る DINOv3、「構造 → 形 → テクスチャ」の 3 段の流れは共通。
  • 違うところ: Pixal3D は、画像から推定したカメラ（MoGe で画角を推定する）を使い、画像の特徴を 3D の格子へ投影する（ComfyUI の Pixal3DConditioning、注意層に投影の重みが足されている）。入力画像の見た目に形を合わせる狙いの作り。
  • この機体には 2 つとも入っている（重みは Pixal3D 5.2 GiB・TRELLIS.2 4.9 GiB）。どちらも ComfyUI の中で使う。入口ページに TRELLIS.2 だけのカードは無い。

入口ページの「Pixal3D」カード（ポート 7861）は、Pixal3D を単独で動かす別の画面（画像 1〜4 枚）。このページの ComfyUI の中の Pixal3D とは別物で、同時には使えない。

どちらを使うか

ワークフローPixal3DTRELLIS.2メモ
01・01b・02・Image_to_3D既定選べる画像から形を作る。どちらでも最後まで動く（下の「目安」に実測）。ただし斧のサンプルの 02 は、TRELLIS.2 だと低ポリが閉じなかった。形の出来は画像によるので、両方試して選ぶ
03使えない必須Pixal3D は推定したカメラから画像を投影するので、自分で作った形にしか色を付けられず、手持ちのメッシュでは黒いテクスチャになる（配布元のノートの説明）。手持ちのメッシュを読む形状エンコーダも TRELLIS.2 のもの

3. 起動して開く

  1. 入口ページの ComfyUI のカードで「起動」を押す。Hunyuan3D・Pixal3D（7861）・Strata・音楽・効果音生成が動いていれば、自動で止まる（GPU を 1 枚で取り合うため）。
  2. Ollama（Qwen のチャット）にモデルが載っていれば、入口ページの案内に従って降ろす。
  3. カードが「稼働中」になったら「開く」か、このページ上の「ComfyUI を開く」で ComfyUI の画面を開く。
  4. 左の Workflows から使うワークフローを開く。
  5. 使い終わったら、入口ページで ComfyUI を「停止」する（GPU を返す）。

Blender のパス（紫の「Blender path」）は設定済み（/snap/blender/current/blender）。変えない。

4. モデルの切り替え方

ワークフローの中のグループ 「Switch Model Here」 に、ノード 「Boolean (Switch to Trellis2)」 がある。この 1 つで、形とテクスチャを作るモデルが決まる。

ノードの値（value）使うモデル既定になっているワークフロー
falsePixal3D01・01b・02・Image_to_3D
trueTRELLIS.203
  1. 01・01b・02 は、開いたときの表示から右へたどると「Switch Model Here」のグループがある（画像の置き場より右）。
  2. ノードの値を切り替えてから Run を押す。切り替えたまま保存（Ctrl+S）すると、そのワークフローはその値で保存される。
  3. Image_to_3D はアプリ表示（入力欄だけの画面）で開く。アプリ表示の入力は「画像・ポリゴン数・テクスチャサイズ」だけで、このスイッチは出ていない。 TRELLIS.2 を使うときはグラフ表示（ノードが並ぶ画面）に切り替えて、同じ名前のノードを true にする。

03 を false（Pixal3D）にすると、テクスチャが黒くなる。03 は true のまま使う。

5. ワークフロー別の手順

結果の GLB は、サーバーの tools/comfyui/vendor/ComfyUI/output/3d/ に残る（ファイル名の後ろに通し番号が付く）。画面では右端のビューアに出る。

01 / 01b — 画像から閉じたメッシュ

  1. Load Image（「Upload Input Image Here」）で画像を選ぶ。1 つの物体が大きく写った画像が向く。背景は自動で取り除く。
  2. 必要なら「Boolean (Switch to Trellis2)」でモデルを選ぶ。
  3. Run を押す。
  4. 結果は「Watertight model」（01）・「Watertight 2K model」（01b）のビューア。ファイルは PixelArtistry_watertight_*.glb・PixelArtistry_watertight_2K_*.glb。

流れ: 形を作る → Quad Reconstruct で整える（01b では bypass）→ WTiVo で閉じる → LODTailor（Blender）で 600 万面以下に減らし閉じたまま保つ → Fast Merge で重なった頂点をまとめる。

01b（2K）は、WTiVo の proxy_points を配布元の 25,000,000 から 20,000,000 に下げてある。配布元の値では WTiVo の出力が 8,255 万面に跳び、この機体の RAM に収まらなかった（2026-11-03）。

02 — 画像からゲーム用の低ポリまで

  1. Load Image で画像を選び、必要ならモデルを選ぶ。
  2. 「A · LODTailor low-poly」の target_tris で低ポリの面数を決める（既定 30,000。キャラクターは 2〜3 万、小物は 500〜1,000）。
  3. Run を押す。
  4. 結果は PixelArtistry_highpoly_*.glb（テクスチャ付きの高ポリ）と PixelArtistry_lowpoly_*.glb（焼き込んだ低ポリ）。

Bake Forger の各マップは 4096px（*_resolution で 2048・8192 にできる）。低ポリに白い斑点が出たら tight_cage_extrusion_factor を上げる（キャラクター 0.0019、硬い物 0.019）。

03 — 手持ちのメッシュに色を付ける

  1. メッシュ（.glb か .obj）をサーバーの tools/comfyui/vendor/ComfyUI/input/ に置く（scp などで送る）。
  2. 「Your mesh」ノードの mesh_filename にファイル名（または絶対パス）を書く。
  3. Load Image に、そのメッシュの元になった画像を選ぶ（テクスチャはこの画像から作る）。
  4. 「Boolean (Switch to Trellis2)」は true（TRELLIS.2）のまま。Run を押す。
  5. 結果は PixelArtistry_textured_*.glb（テクスチャを付けたメッシュ）と PixelArtistry_lowpoly_*.glb。

600 万面を超えるメッシュは先に 600 万面へ減らす（UV 展開を速くするため）。低ポリが要らなければ「2 Low-Poly + Bake」のグループを bypass（Ctrl+B）する。

Image_to_3D — テクスチャ付きの 3D を手早く

  1. Load Image で画像を選ぶ（ドラッグ＆ドロップでもよい）。
  2. 必要なら ポリゴン数（既定 700,000。0 は間引かない）と テクスチャサイズ（既定 4096。256〜8192 の 256 の倍数）を変える。
  3. Run を押す。結果は Save 3D のビューア。ファイルは ComfyUI_*.glb。

TRELLIS.2 で作るときだけ、グラフ表示に切り替えてスイッチを true にする（上の「モデルの切り替え方」）。

  • 「閉じている」は、同じ位置の頂点を溶接したあとで境界辺 0・非多様体辺 0 のこと（measure_mesh.py で測った）。殻はつながった塊の数。
  • 02 の TRELLIS.2 は、低ポリ化（LODTailor、30,000 面）のあとで網が開き、最後の Fast Merge が距離を変えて 100 回試しても閉じられず、元の網のまま返した （Pixal3D は同じ段で開いても、Fast Merge の 7 回目で閉じた）。
  • TRELLIS.2 は、形を作る最後の段（KSampler）が 80 秒（Pixal3D は 47 秒）、Quad Reconstruct が 42 秒（同 15 秒）かかり、01 は約 1 分、 02 は約 2.5 分長かった（02 は閉じられなかった Fast Merge の 100 回の試行に 62 秒）。Pixal3D は代わりにカメラの推定（MoGe と Pixal3DConditioning、約 17 秒）を行う。Image_to_3D は TRELLIS.2 が 222 秒、Pixal3D が 167〜173 秒。
  • 01b は TRELLIS.2 でも、proxy_points 20M のまま RAM 31.4 GiB で通った。

02 で閉じた低ポリが要るときは Pixal3D（既定）を使う。TRELLIS.2 で開いたときに Run をやり直して閉じるか（構造の seed は毎回変わる）は、確かめていない。

7. 困ったとき

症状対処
穴が残ったもう一度 Run を押す（構造の seed は毎回変わる）。モデルを切り替えて試すのもよい。
ComfyUI が止まる・極端に遅くなる（RAM が足りない）01b なら WTiVo の proxy_points をさらに下げる（16,000,000 や 12,000,000）か、01（1536）を使う。ほかの重いアプリを閉じる。
02 の低ポリが閉じない（TRELLIS.2 のとき）Pixal3D（false）に戻して流す。斧のサンプルでは Pixal3D で閉じ、TRELLIS.2 では閉じなかった。
03 のテクスチャが黒い「Boolean (Switch to Trellis2)」が false（Pixal3D）になっている。true に戻す。
Blender で開くと穴だらけに見えるGLB を読み込むとき「Merge Vertices」を付ける（UV の継ぎ目で頂点が分かれていて、開いた辺に見える）。閉じているかは 3D Print Toolbox の Check All で見る。
02・03 の Bake Forger だけ数分長い機体を起動して最初の 1 回は、Blender の OptiX の準備で 3〜4 分長くかかることがある（2026-10-03 に 270 秒、2 回目は 74 秒）。
「起動」を押しても ComfyUI が開かない別のプロジェクトが GPU を使っていないか、入口ページの GPU の表示を見る。数十秒〜数分待ってから開き直す。

8. 画面を使わずに流す

サーバーの上で、リポジトリのルートから。--backend で「Boolean (Switch to Trellis2)」を切り替えて投入する（pixal3d = false、trellis2 = true）。記録は output/localai_runs/<tag>/。

tools/comfyui/.venv/bin/python tools/comfyui/scripts/run_workflow.py run \
  tools/comfyui/vendor/ComfyUI/user/default/workflows/PixelArtistry/PixelArtistry_01_Image_to_Watertight_Mesh.json \
  --image viking_wolf_rune_axe.png --backend trellis2 --tag my_t2_wf01 --free-before --monitor --guard-mem-gib 43

画像は tools/comfyui/vendor/ComfyUI/input/ に置いた名前で指定する。--guard-mem-gib 43 は RAM が 43 GiB を超えたら止める歯止め。詳しくは tools/comfyui/README.md の「画面を使わずにワークフローを通す」。

9. 確かめていないこと

  • 実測は斧のサンプル 1 枚だけ。ほかの画像で時間・RAM・面数が同じになるとは限らない。
  • Pixal3D と TRELLIS.2 のどちらの出来が良いかは、画像によるため決めていない。
  • ComfyUI の画面での見え方（日本語ノートの位置、Image_to_3D の表示の切り替えの場所）は、画面写しで確かめていない。

根拠と詳しい記録: tools/comfyui/README.md（「2K（01b）をこの機体で通す設定」「実機試験の結果」）。
