動画生成の使い方（HunyuanVideo 1.5 / Kandinsky 6.0 Lite / LTX 2.5 Fast）

← 入口ページ ComfyUI を開く（ポート 8188）→

文章や画像 1 枚から短い動画を作る 3 つのモデルを、ComfyUI のワークフローとして入れてある。 この機体（NVIDIA A30・VRAM 24 GiB・RAM 64 GB）で動くように、重みの形式（量子化）を選んである。 Kandinsky 6.0 Lite と LTX 2.5 Fast は音声付きの動画を作る。HunyuanVideo 1.5 は音声なし。

1. できること（3 つのモデルの違い）

ComfyUI の左の Workflows → Video フォルダに 8 本ある。どれも開くと左上に緑の日本語ノート「使い方（日本語・この機体）」がある。

モデルワークフロー入力出力（既定）音声大きさ
HunyuanVideo 1.5（Tencent）HunyuanVideo15_T2V
HunyuanVideo15_I2V		 文章 / 文章＋最初のコマの画像1280×720・121 コマ（24 fps で約 5 秒）なし8.3B
Kandinsky 6.0 Lite（Kandinsky Lab）Kandinsky6_Lite_T2V / _I2V（50 ステップ）
Kandinsky6_LiteDistill_T2V / _I2V（10 ステップ）		 映像と音の説明文 / ＋最初のコマの画像864×480・121 コマ（24 fps で約 5 秒）あり（44.1 kHz）3B
LTX 2.5 Fast（Lightricks）LTX25_Fast_T2V
LTX25_Fast_I2V		 文章 / 文章＋最初のコマの画像約 1280×720・5 秒・24 fps（低い解像度で作って 2 倍に上げる 2 段）あり22B（distilled）
  • T2V は文章 → 動画、I2V は画像（最初のコマ）＋文章 → 動画。
  • 「LTX 2.5 Fast」は LTX 2.5 の distilled（少ないステップで作るように学習し直した）版。Lightricks の API と LTX Desktop がこの名前で呼んでいる。
  • Kandinsky の Lite と Lite distill は同じ 3B。distill は 10 ステップで速く、Lite は 50 ステップで丁寧に作る。迷ったら distill から試す。
  • プロンプトは英語で書く（HunyuanVideo は中国語も可）。日本語はどれも弱い。

2. 起動して開く

  1. 入口ページ（このページの左上の「← 入口ページ」）の ComfyUI のカードで「起動」を押す。Hunyuan3D・Pixal3D・Strata・音楽・効果音生成が動いていれば自動で止まる。
  2. Open WebUI で Qwen を使った直後は、入口ページの上の帯に Qwen が載っていると出る。案内に従って降ろす（VRAM を空ける）。
  3. カードが「稼働中」になったら、上の「ComfyUI を開く」を押す。
  4. 左の Workflows（ワークフロー）→ Video → 使うものを開く。
  5. プロンプト（と画像）を変えて Run を押す。できた mp4 は右端の Save Video に出て、サーバーの tools/comfyui/vendor/ComfyUI/output/video/ に残る。

最初の 1 本は重みをディスクから読むので、2 本目より数分長くかかる。動画は 1 本ずつ作る。

3. ワークフロー別の手順

HunyuanVideo 1.5（HunyuanVideo15_T2V / HunyuanVideo15_I2V）

  • プロンプト: CLIP Text Encode (Positive Prompt)。出てほしくないものは Negative に書く。
  • I2V の画像: グループ「Step 2 - Upload start_image」の Load Image。
  • 長さ: T2V は EmptyHunyuanVideo15Latent、I2V は HunyuanVideo15ImageToVideo の length（4 の倍数＋1。49 で約 2 秒）。
  • 1080p にする後段: グループ「Video Upscale 1080P (Ctrl-B to enable)」を選んで Ctrl+B で有効にする（既定は切ってある）。出力は 1920×1072。33 コマで約 11 分（720p の本体 5.5 分＋後段 4 分＋デコード）。細部は増えるが、建物などに細かい格子状の模様が出ることがある。デコード中に「Ran out of memory … retrying with tiled VAE decoding」と出るのは、ComfyUI が自動でタイル分割に切り替えたためで、そのまま終わる。

LTX 2.5 Fast（LTX25_Fast_T2V / LTX25_Fast_I2V）

  • 中央の大きなノード（subgraph「Text to Video (LTX-2.5)」/「Image to Video (LTX-2.5)」）に入力がまとまっている。
  • プロンプト: prompt。映像と一緒に鳴らしたい音（声・効果音・環境音）も書く。
  • 長さ: duration（秒）。幅・高さは左の Resolution Selector（縦横比とメガピクセル）が決める。
  • I2V の画像: Load First Frame。
  • prompt_enhance（Gemma 4 E2B でプロンプトを膨らませる）は切ってある。入れると 1〜2 分長くなる。

Kandinsky 6.0 Lite / Lite distill（Kandinsky6_*）

  • プロンプト: ノード「Prompt（映像 video_caption と音 audio_caption）」。video_caption に映像、audio_caption に音を書く。
  • 出てほしくないもの: その下の「Negative video and audio prompt」。
  • I2V の画像: Load Image（864×480 に合わせて中央で切り抜かれる）。
  • 大きさと長さ: Kandinsky6EmptyLatent の width・height（16 の倍数）・length（4 の倍数＋1）。
  • distill は Kandinsky 6 Sampler の CFG を 1、denoise を 1 から変えると止まる（PiFlow の決まり）。

4. A30 向けに変えたところ（量子化）

A30 は VRAM 24 GiB で、FP8 の演算器を持たない。FP8・GGUF の重みは ComfyUI が計算の直前に bf16 へ戻すので動く（速さは bf16 と同じか少し遅い）。 VRAM に入りきらない重みは、ComfyUI が入る分だけ載せて残りを RAM に置く。どの重みも Hugging Face のライセンス同意（gated）が要らないものを選んだ。

モデル部品使う重み大きさ公式との違い
HunyuanVideo 1.5変換器（720p）fp1616.6 GBテンプレートと同じ
文字エンコーダ Qwen2.5-VL 7Bfp8_scaled9.4 GBテンプレートと同じ
1080p 化の変換器fp8_scaled8.3 GBテンプレートの fp16（16.7 GB）から替えた
LTX 2.5 Fast変換器（22B distilled）GGUF UD-Q4_K_XL（unsloth）14.0 GB公式の int8（21.5 GB、gated）から替えた
文字エンコーダ Gemma 4 12Bbf1626.3 GB公式の int8（15.4 GB）は gated
動画の VAE畳み込み版 bf161.5 GB公式の拡散デコーダ版は gated
Kandinsky 6.0 Lite変換器（3B）bf167.5 GB（distill 6.4 GB）上流の例の Pro distill（29B）から替えた
文字エンコーダ Qwen2.5-VL 7Bfp8_scaled9.4 GB上流の bf16（16.6 GB）から替えた。HunyuanVideo と共用
プロンプトの書き足し・超解像外した—上流の例は Qwen3.5 9B（19 GB）と別の拡張 kandinsky6-sr を使う

5. 目安（この機体の実測）

2026-11-06 に、各ワークフローを既定の設定のまま 1 本ずつ流して測った（ほかに GPU を使う作業が無い状態）。どれも最後まで通り、音声付きのものは mp4 に音が入った。

ワークフロー出力かかった時間RAM（最大）
Kandinsky6_LiteDistill_T2V / _I2V864×480・5 秒・音声あり2.4 分10 GiB
Kandinsky6_Lite_T2V / _I2V864×480・5 秒・音声あり19 分10 GiB
LTX25_Fast_T2V / _I2V1280×704・5 秒・音声あり1.5 分17 GiB
HunyuanVideo15_T2V / _I2V1280×720・5 秒・音声なし50 分22 GiB
  • まず試すなら LTX 2.5 Fast か Kandinsky の LiteDistill。どちらも 5 秒の動画が 1〜3 分でできる。
  • HunyuanVideo 1.5 は長さを伸ばすと急に遅くなる。33 コマ（約 1.4 秒）なら 6 分、121 コマ（約 5 秒）だと 50 分。試すときは length を 33〜49 にする。
  • VRAM はどれも 23〜24 GiB 使う（ComfyUI が空いている分を使い切る）。ほかの GPU のサービスと同時には動かせない。
  • ComfyUI を起動して最初の 1 本は、重みをディスクから読むので 1〜数分長くかかる。
  • 違うモデルを何本も続けると、前の重みが RAM に残って swap を使う（8 本続けて最大 5 GiB）。止まりはしないが、モデルを替えるときは入口ページで ComfyUI を止めて起動し直すと軽くなる。

6. 困ったとき

  • 赤い枠のノードに「Value not in list」: 重みが無い。サーバーで tools/comfyui/run-comfyui fetch-models --video を流す（合計 約 111 GiB）。1 つのモデルだけなら --group hunyuanvideo15・ltx25・kandinsky6。
  • 「Unet Loader (GGUF)」や「Kandinsky 6 Sampler」が赤い（ノードが無い）: custom_nodes の読み込みに失敗している。サーバーで tools/comfyui/run-comfyui doctor --skip-selftest を流して NG の行を見る。
  • CUDA out of memory: Ollama の Qwen や、別の作業が GPU を使っていないかを入口ページの上の帯で見る。長さ（length / duration）か解像度を下げる。
  • 2 本目から遅い・PC が重い: 前の重みが RAM に残っている。入口ページで ComfyUI を止めて起動し直す。
  • Kandinsky の distill で「requires CFG=1 and denoise=1」: Kandinsky 6 Sampler の cfg と denoise を 1 に戻す。

7. 画面を使わずに流す

サーバーで ComfyUI が動いているとき、写しを API 形式に変えて流せる（LTX の subgraph も展開する）。結果は output/localai_runs/<tag>/run.json に残る。

tools/comfyui/.venv/bin/python tools/comfyui/scripts/run_workflow.py run \
  tools/comfyui/vendor/ComfyUI/user/default/workflows/Video/Kandinsky6_LiteDistill_T2V.json \
  --tag k6-distill --monitor --free-before

9. 確かめていないこと

  • 画面での見え方（日本語ノートの位置・subgraph の入力の並び）は、画面写しで確かめていない。
  • 出来の良し悪しは、プロンプトと画像によるため比べていない（どれもテンプレートの例のプロンプトで、破綻のない映像になることは確かめた）。
  • 1080p の後段で出る格子状の模様が、fp8_scaled の重み（公式は fp16）のせいかどうかは確かめていない（EasyCache を切っても変わらなかった）。
  • HunyuanVideo の EasyCache（本体側。速くなるが質が落ちる）でどれだけ速くなるかは測っていない。
